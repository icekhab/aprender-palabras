# Курсы и приглашения

## 1. Цель

**Курс** — контейнер упорядоченных уроков со словами. Курсы доступны **только**
пользователям с ролью `teacher` или `admin`. Роль `user` не видит раздел
Cursos, не принимает приглашения и не проходит курсы.

Teacher/admin создаёт курс, приглашает других teacher/admin, после
подтверждения у каждого участника свой текущий урок. Создатель видит
участников, меняет их текущий урок и завершает курс за них.

Уроки без курса не существуют. Поведение урока — [02-lessons.md](./02-lessons.md);
здесь — роли, приглашения, статусы, UI, активность и тренажёр.

Интерфейс на испанском. Экран раздела — **Cursos** (скрыт для `user`).

### 1.1. Роли и доступ

| Роль | Курсы |
|---|---|
| `user` | Нет доступа (UI и API) |
| `teacher` | Полный доступ к своим и принятым курсам |
| `admin` | Как teacher + права admin на слова |

### 1.2. Demotion создателя (`teacher`/`admin` → `user`)

Для курсов, где пользователь был `createdBy`:

- у оставшихся участников с teacher/admin курс показывается как
  **деактивированный** (см. эффективную активность §7);
- нельзя менять текущий урок, завершать, править контент, приглашать;
- курс **не** даёт уроковое окно в ежедневный пул;
- карточки, уже попавшие в личный словарь участников, **остаются** и
  **продолжают** участвовать в ежедневных тренировках как обычные карточки
  словаря;
- у самого demoted-пользователя раздела курсов больше нет.

## 2. Данные курса

Курс содержит:

- уникальный идентификатор;
- название;
- создателя (`createdBy`);
- признак активности набора (`active`, по умолчанию `true`) — выключает
  создатель для всех;
- упорядоченный список уроков;
- список участий (membership).

### Ограничения

1. Название обязательно после trim.
2. Создатель всегда является участником со статусом `accepted` с момента
   создания курса (подтверждение не требуется).
3. Один пользователь — не более одного membership на курс.
4. Приглашать можно только если в курсе есть хотя бы один урок.
5. Приглашать можно только существующего пользователя с ролью `teacher`
   или `admin` (логин без учёта регистра). Email не используется. Нет в БД
   или роль `user` — приглашение не создаётся, понятная ошибка.
6. Неэффективный набор (см. §7) — нельзя приглашать; не даёт уроковое окно
   в ежедневный пул.

## 3. Участие (membership)

| Статус | Смысл |
|---|---|
| `pending` | Приглашение отправлено, ждёт ответа на экране Cursos |
| `accepted` | Подтверждено; курс в прохождении (не завершён) |
| `completed` | Курс завершён для этого участника |

У каждого `accepted` / `completed` участия хранится **свой** текущий урок
курса (`currentLesson`), независимый от других участников.

Отклонение приглашения **удаляет** membership (отдельный статус `rejected`
не хранится). Создатель может пригласить снова.

### 3.1. Когда курс считается завершённым для участника

Membership переходит в `completed`, если выполняется любое из условий:

1. **Автоматически:** текущий урок участника — **последний** урок курса
   (после смены текущего на последний урок).
2. **Вручную:** участник или создатель (от имени участника) нажимает
   «завершить курс».

Завершённый для участника курс:

- показывается в списке со статусом завершён;
- **не** кормит ежедневный пул тренажёров для этого участника;
- остаётся доступен для просмотра; создатель / участник могут снова
  выставить текущий урок (тогда статус снова `accepted`, если текущий
  не последний — либо остаётся логика: смена текущего с последнего на
  более ранний возвращает в `accepted`).

Целевое правило возврата: любая смена текущего урока на **не последний**
снимает `completed` → снова `accepted`. Смена на последний снова даёт
`completed`.

### Права

Все колонки ниже предполагают, что актор — `teacher` или `admin`, и курс
**эффективно активен** (§7), кроме просмотра деактивированного.

| Действие | Создатель | Участник `accepted`/`completed` | `pending` |
|---|---|---|---|
| Редактировать название / `active` курса | да | нет | нет |
| Создавать, упорядочивать, удалять уроки и слова курса | да | нет | нет |
| Смотреть уроки и свой прогресс | да | да | нет |
| Менять **свой** текущий урок | да | да | нет |
| Завершить курс **для себя** | да | да | нет |
| Менять текущий урок / завершить **для другого** | да | нет | нет |
| Список участников курса | да | нет | нет |
| Список всех приглашённых по своим курсам | да | нет | нет |
| Страница пользователя в контексте своих курсов | да | нет | нет |
| Принять / отклонить приглашение | — | — | да |
| Пригласить по логину | да (≥1 урок, эффективен) | нет | нет |

На деактивированном курсе (в т.ч. demotion создателя) — только просмотр
статуса «деактивирован»; смена current / complete / invite / edit запрещены.

Прогресс карточек остаётся личным (`пользователь + слово`).

## 4. Создание курса

Только `teacher` или `admin`.

1. Пользователь вводит название.
2. Создаётся курс с `active = true`.
3. Создатель автоматически получает membership `accepted`.
4. Уроков пока нет — приглашать нельзя.
5. При появлении первого урока у accepted-участника без текущего урока
   текущим становится **первый** урок; то же при accept приглашения.

Пустой курс допустим для подготовки контента.

## 5. Приглашение

### 5.1. Предусловия

- текущий пользователь — создатель курса и `teacher`/`admin`;
- курс эффективно активен (§7);
- в курсе есть минимум один урок;
- указанный логин существует и имеет роль `teacher` или `admin`;
- у этого пользователя ещё нет membership в этом курсе.

### 5.2. Поведение

1. Создатель вводит логин приглашаемого.
2. Нет пользователя / роль `user` — ошибка, membership не создаётся.
3. Иначе — membership `pending`.
4. Доставка только в приложении: блок на **Cursos** у приглашённого (§10).

Повторное приглашение при существующем `pending` / `accepted` /
`completed` не создаёт вторую запись (для `completed` — отдельное решение
при реализации: либо запрет, либо повторный invite недоступен пока есть
запись; по умолчанию **запрет**, пока создатель не удалит участие — если
удаление не предусмотрено, повторный invite к `completed` тоже запрещён).

### 5.3. Подтверждение и отклонение

**Принять:**

1. Статус → `accepted`.
2. Курс появляется в списке курсов.
3. Текущий урок = первый.
4. Синхронизация словаря по окну `предыдущие + текущий + следующий`
   ([02-lessons.md](./02-lessons.md) §7).

**Отклонить:**

1. Membership удаляется.
2. Блок приглашения исчезает у приглашённого.
3. У создателя участник больше не числится pending.

## 6. Текущий урок и завершение

- Участник меняет текущий урок по правилам [02-lessons.md](./02-lessons.md) §7
  для себя.
- Создатель может сделать то же от имени другого `accepted` / `completed`
  участника.
- Кнопка «завершить курс» доступна участнику для себя и создателю для
  любого принятого участника.
- Если после смены текущий = последний урок → статус `completed`.

Отображение для создателя по участнику:

| Состояние | Что показать |
|---|---|
| `pending` | ожидает подтверждения |
| `accepted`, есть уроки | текущий урок и следующий (если есть) |
| `accepted`, уроков нет | подтверждён (без уроков) |
| `completed` | курс завершён |

## 7. Эффективная активность

Курс **эффективно активен**, только если одновременно:

1. `Course.active = true` (создатель не выключил набор), и
2. создатель (`createdBy`) сейчас имеет роль `teacher` или `admin`.

Иначе курс **деактивирован** (в UI — как неактивный), даже если флаг
`active` в БД ещё `true`.

Создатель с ролью teacher/admin может явно выставить `active = false`.

Это **не** то же самое, что `completed` у участника.

Последствия деактивации (флаг или demotion):

- уроковое окно курса **не** входит в ежедневный пул;
- новые приглашения запрещены;
- нельзя менять текущий урок / завершать / править контент;
- существующие membership сохраняются;
- карточки уже в личном словаре **остаются** и участвуют в тренировках
  по правилам словаря (не удаляются).

## 8. Связь с ежедневным тренажёром

Для урокового окна пула дня (актор — teacher/admin):

1. Membership `accepted` в курсах **эффективно активных** (§7).
2. Окно `предыдущие + текущий + следующий` по его current.
3. Объединение окон + карточки словаря (в т.ч. когда-то добавленные из
   уже деактивированных курсов).
4. Правила [03-daily-training.md](./03-daily-training.md).

`completed`, `pending` и неэффективные курсы в **уроковое** окно не входят;
словарь при этом не очищается.

## 9. Миграция существующих данных

1. Для каждого пользователя с уроками — личный курс (создатель = он,
   membership `accepted`, `active = true`).
2. Уроки переносятся с сохранением порядка.
3. Бывший `currentLesson` → membership; last → `completed`, иначе `accepted`.
4. Чтобы личный курс оставался эффективно активным, создателю нужна роль
   `teacher` или `admin` (иначе курс сразу деактивирован по §7).

## 10. Интерфейс

Язык UI — испанский. Раздел **Cursos** только для `teacher`/`admin`
(пункт меню скрыт для `user`). Уроки открываются внутри курса.

### 10.1. Страница Cursos

Сверху контента — блок **приглашений** (если есть `pending`):

- название курса (и при необходимости кто пригласил);
- действия принять / отклонить.

Ниже — **список курсов** пользователя (созданные им и принятые /
завершённые):

| Состояние прохождения | Подпись в списке |
|---|---|
| не завершён (`accepted`) | текущий урок (номер / название) |
| завершён (`completed`) | статус завершён (например Completado) |
| все уроки по сути пройдены (current = last) | то же, что завершён |

**Сортировка:** сначала эффективно активные с незавершённым прохождением,
затем завершённые, деактивированные — в конце (или с пометкой
деактивирован). Внутри группы — стабильный порядок (при реализации).

Создатель дополнительно видит навигацию к **списку всех приглашённых**
(§10.4).

### 10.2. Страница курса

- Список уроков (статусы относительно моего current, если участник).
- При эффективной активности: отметить current, завершить курс.
- Создатель (если ещё teacher/admin и курс эффективен): edit уроков,
  invite, участники (§10.3), `active`.
- Если курс деактивирован — read-only, статус деактивирован.

### 10.3. Участники внутри курса (только создатель)

Список всех membership курса:

- сортировка: сначала **не завершившие** (`pending`, затем `accepted`),
  затем `completed`;
- для каждого — статус и текущий/следующий урок по §6;
- переход к действиям над участником (смена текущего, завершить) и/или
  на страницу пользователя в контексте курсов.

### 10.4. Все приглашённые и страница пользователя (создатель)

1. **Список всех пользователей**, которых создатель когда-либо пригласил
   хотя бы на один свой курс (уникальные пользователи по всем его курсам).
2. Переход на **страницу пользователя в контексте курсов**: только курсы,
   куда **этот создатель** добавил данного пользователя (не чужие курсы
   других создателей).
3. На этой странице / внутри каждого такого курса создатель может менять
   текущий урок пользователя и завершать курс для него — те же правила,
   что в §6.

## 11. Ошибки и пограничные случаи

| Ситуация | Поведение |
|---|---|
| Роль `user` открывает Cursos / API курсов | Нет доступа / `403` |
| Приглашение при 0 уроках | Запрещено |
| Логин не найден или роль `user` | Membership не создаётся, ошибка |
| Курс неэффективен (§7) | Нельзя invite / current; нет урокового окна в пуле |
| Demotion создателя | Курс деактивирован; словарь участников без удаления |
| Отклонение invite | Membership удалён |
| Current = последний урок | Membership → `completed` |
| Ручное завершение | Membership → `completed` |
| Смена current на не последний | `completed` → `accepted` |
| Два эффективных незавершённых курса | Окна объединяются в пуле дня |
| Создатель приглашает себя | Не нужно: уже `accepted` |

## 12. Критерии приёмки

- **COURSE-01:** создавать курс могут только `teacher`/`admin`; создатель сразу
  `accepted`.
- **COURSE-02:** уроки только внутри курса; роль `user` не видит курсы.
- **COURSE-03:** приглашение невозможно без ≥1 урока и без эффективной активности.
- **COURSE-04:** invite несуществующего или `user` не создаёт membership.
- **COURSE-05:** pending на Cursos; accept/reject без email (только teacher/admin).
- **COURSE-06:** после accept current = первый; словарь по окну уроков.
- **COURSE-07:** reject удаляет membership.
- **COURSE-08:** участник — свой current/complete; создатель — ещё чужие
  (на эффективном курсе).
- **COURSE-09:** current = last или ручное complete → `completed`.
- **COURSE-10:** список: незавершённые эффективные сверху; Completado / деактивирован.
- **COURSE-11:** участники курса: не завершившие сверху.
- **COURSE-12:** список приглашённых → страница пользователя в контексте курсов.
- **COURSE-13:** неэффективный курс без урокового окна и без новых invite;
  `completed` membership без урокового окна.
- **COURSE-14:** пул объединяет окна всех `accepted` + эффективно активных курсов;
  слова уже в словаре остаются в тренировках.
- **COURSE-15:** участник не редактирует чужой контент курса.
- **COURSE-16:** demotion создателя → деактивация; словарь не чистится.
- **COURSE-17:** миграция старых уроков в личный курс; last → completed.
