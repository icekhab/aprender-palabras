# Курсы и приглашения

## 1. Цель

**Курс** — контейнер упорядоченных уроков со словами. Teacher/admin создаёт
курс для учеников и приглашает **любого** существующего пользователя
(роли `user`, `teacher` или `admin`). После подтверждения у каждого
участника свой текущий урок. Редактировать контент курса может только
создатель; остальные — смотреть и управлять своим прогрессом. Создатель
также может менять прогресс ученика.

Уроки без курса не существуют. Поведение урока — [02-lessons.md](./02-lessons.md);
здесь — роли, приглашения, статусы, UI, активность и тренажёр.

Интерфейс на испанском. Меню: **Mis cursos** (все auth) и
**Gestión de cursos** (`teacher`/`admin`).

### 1.1. Роли и доступ

| Роль | Курсы |
|---|---|
| `user` | Видит Cursos; принимает invite; смотрит принятые курсы; свой прогресс. Не создаёт, не invite, не правит контент |
| `teacher` | Как `user` + создание курсов / invite / edit своих курсов / Alumnos |
| `admin` | Как teacher + права admin на слова |

### 1.2. Demotion создателя (`teacher`/`admin` → `user`)

Для курсов, где пользователь был `createdBy`:

- у участников курс показывается как **деактивированный** (см. эффективную
  активность §7);
- нельзя менять текущий урок, править контент, приглашать;
- курс **не** даёт уроковое окно в ежедневный пул;
- карточки, уже попавшие в личный словарь участников, **остаются** и
  **продолжают** участвовать в ежедневных тренировках как обычные карточки
  словаря;
- demoted-пользователь по-прежнему видит Cursos (как `user`: свои принятые
  курсы и приглашения), но не может создавать / править свои бывшие курсы.

## 2. Данные курса

Курс содержит:

- уникальный идентификатор;
- название;
- создателя (`createdBy`);
- признак активности набора (`active`, по умолчанию `true`) — выключает
  создатель для всех;
- упорядоченный список уроков;
- список участий (membership).

### Ограничения

1. Название обязательно после trim.
2. Создатель имеет доступ к курсу как создатель (без обязательного
   membership). Если создатель приглашает **себя** — membership сразу
   `accepted` (без pending), current = первый урок, словарь как при accept.
3. Один пользователь — не более одного membership на курс.
4. Приглашать можно только если в курсе есть хотя бы один урок.
5. Приглашать можно любого существующего пользователя (логин без учёта
   регистра). Email не используется. Нет в БД — приглашение не создаётся.
6. Неэффективный набор (см. §7) — нельзя приглашать; не даёт уроковое окно
   в ежедневный пул.

## 3. Участие (membership)

| Статус | Смысл |
|---|---|
| `pending` | Приглашение отправлено, ждёт ответа на экране Cursos |
| `accepted` | Подтверждено; у участника свой текущий урок |

У каждого `accepted` участия хранится **свой** текущий урок курса
(`currentLesson`), независимый от других участников. Отдельного статуса
«завершён» нет: даже на последнем уроке membership остаётся `accepted`
и продолжает кормить уроковое окно пула.

Отклонение приглашения **удаляет** membership (отдельный статус `rejected`
не хранится). Создатель может пригласить снова.

### Права

Колонки ниже для эффективно активного курса (§7), кроме просмотра
деактивированного. Участник может быть любой роли.

| Действие | Создатель (`teacher`/`admin`) | Участник `accepted` | `pending` |
|---|---|---|---|
| Редактировать название / `active` курса | да | нет | нет |
| Создавать, упорядочивать, удалять уроки и слова курса | да | нет | нет |
| Смотреть уроки и свой прогресс | да | да | нет |
| Менять **свой** текущий урок | да (если есть membership) | да | нет |
| Менять текущий урок **для другого** | да | нет | нет |
| Список участников курса | да | нет | нет |
| Список учеников (Alumnos) по своим курсам | да | нет | нет |
| Страница пользователя в контексте своих курсов | да | нет | нет |
| Принять / отклонить приглашение | — | — | да |
| Пригласить по логину | да (≥1 урок, эффективен) | нет | нет |
| Убрать участника с курса | да | нет | нет |
| Выйти из курса (удалить своё membership) | да (если есть membership) | да | да |

Удаление membership (создателем или самим участником) **не** чистит
словарь: уже попавшие карточки остаются. После удаления можно пригласить
снова. На деактивированном курсе смена current / invite / edit запрещены;
страница курса для участников недоступна.

Прогресс карточек остаётся личным (`пользователь + слово`).

## 4. Создание курса

Только `teacher` или `admin`.

1. Пользователь вводит название.
2. Создаётся курс с `active = true`.
3. Создатель видит курс в списке как создатель (membership не обязателен).
4. Уроков пока нет — приглашать нельзя.
5. При accept приглашения текущим становится **первый** урок; то же при
   появлении первого урока у accepted-участника без текущего.

Пустой курс допустим для подготовки контента.

## 5. Приглашение

### 5.1. Предусловия

- текущий пользователь — создатель курса и `teacher`/`admin`;
- курс эффективно активен (§7);
- в курсе есть минимум один урок;
- указанный логин существует (любая роль);
- у этого пользователя ещё нет membership в этом курсе.

### 5.2. Поведение

1. Создатель вводит логин приглашаемого.
2. Нет пользователя — ошибка, membership не создаётся.
3. Свой логин — сразу `accepted` (+ current / словарь, как accept).
4. Чужой логин — membership `pending`; блок на **Mis cursos** у invitee.

Повторное приглашение при существующем `pending` / `accepted` не создаёт
вторую запись (`409`). После удаления membership invite снова возможен.

### 5.3. Подтверждение и отклонение

**Принять:**

1. Статус → `accepted`.
2. Курс появляется в списке курсов.
3. Текущий урок = первый.
4. Синхронизация словаря по окну `предыдущие + текущий + следующий`
   ([02-lessons.md](./02-lessons.md) §7).

**Отклонить:**

1. Membership удаляется.
2. Блок приглашения исчезает у приглашённого.
3. У создателя участник больше не числится pending.

## 6. Текущий урок

- Участник меняет текущий урок по правилам [02-lessons.md](./02-lessons.md) §7
  для себя.
- Создатель может сделать то же от имени другого `accepted` участника.
- Отдельного действия «завершить курс» нет.

Отображение для создателя по участнику:

| Состояние | Что показать |
|---|---|
| `pending` | ожидает подтверждения |
| `accepted`, есть уроки | выбор текущего урока |
| `accepted`, уроков нет | подтверждён (без уроков) |

## 7. Эффективная активность

Курс **эффективно активен**, только если одновременно:

1. `Course.active = true` (создатель не выключил набор), и
2. создатель (`createdBy`) сейчас имеет роль `teacher` или `admin`.

Иначе курс **деактивирован** (в UI — как неактивный), даже если флаг
`active` в БД ещё `true`.

Создатель с ролью teacher/admin может явно выставить `active = false`.

Последствия деактивации (флаг или demotion):

- уроковое окно курса **не** входит в ежедневный пул;
- новые приглашения запрещены;
- нельзя менять текущий урок / править контент;
- существующие membership сохраняются;
- **участники** не открывают страницу курса (в списке Cursos —
  Desactivado, без перехода); **создатель** открывает (реактивация /
  read-only);
- карточки уже в личном словаре **остаются** и участвуют в тренировках
  по правилам словаря (не удаляются).

## 8. Связь с ежедневным тренажёром

Для урокового окна пула дня (актор — любая роль с `accepted` membership):

1. Membership `accepted` в курсах **эффективно активных** (§7).
2. Окно `предыдущие + текущий + следующий` по его current.
3. Объединение окон + карточки словаря (в т.ч. когда-то добавленные из
   уже деактивированных курсов).
4. Правила [03-daily-training.md](./03-daily-training.md).

`pending` и неэффективные курсы в **уроковое** окно не входят; словарь при
этом не очищается. Участник на последнем уроке остаётся `accepted` и
продолжает давать окно.

## 9. Миграция существующих данных

Прод пуст — массовая миграция уроков в курсы не выполнялась. Если появятся
старые данные без курса: личный курс на создателя-teacher/admin, уроки с
сохранением порядка, current → membership.

## 10. Интерфейс

Язык UI — испанский. Два пункта меню аккаунта:

| Пункт | Кто видит | Путь |
|---|---|---|
| **Mis cursos** | все auth | `/cursos` — режим ученика |
| **Gestión de cursos** | `teacher` / `admin` | `/cursos/gestion` — режим создателя |

Учитель, который ещё и ученик чужого курса, видит оба пункта.

### 10.1. Mis cursos (ученик)

Список: `pending` invites + `accepted` memberships (свои созданные без
membership сюда не попадают).

- empty: «Aún no hay cursos»;
- блок **Invitaciones** (принять / отклонить);
- открытие курса → режим ученика (`/cursos/:id`);
- деактивированный в списке без перехода.

Подпись: текущий урок или Desactivado · N lecciones.

### 10.1b. Gestión de cursos (создатель)

Список: только курсы, где я `createdBy`. **Nuevo curso**, **Alumnos**.

- empty + CTA создать;
- открытие → режим создателя (`/cursos/gestion/:id`);
- деактивированный открывается (Reactivar).

### 10.2. Страница курса

**Режим ученика** (`/cursos/:id`):

- прогресс уроков, подпись **Actual** (только для текущего);
- Marcar actual, Salir del curso;
- без edit / Participantes / Desactivar.

**Режим создателя** (`/cursos/gestion/:id`):

- edit / reorder / delete уроков, Nueva lección, Participantes, Desactivar;
- **без** прогресса уроков и без Marcar actual / Salir;
- деактивированный: Reactivar + read-only.

### 10.3. Участники внутри курса (только создатель)

Заголовок: `{название курса} · Participantes`.

Список всех membership курса:

- кнопки **Invitar** (эффективный курс, ≥1 урок) и **Eliminar**;
- режим **Eliminar:** вместо них **Guardar** / **Cancelar**; слева от
  логина — иконка удаления (сразу скрывает строку локально); действия
  справа недоступны; **Guardar** → confirm → batch удаление membership
  (словарь не трогаем); **Cancelar** откатывает скрытие;
- сортировка: `pending`, затем `accepted` не на последнем уроке, затем
  `accepted` на последнем;
- для каждого — статус pending / смена current;
- переход на страницу пользователя в контексте курсов (вне режима
  удаления).

### 10.4. Alumnos и страница пользователя (создатель)

1. **Список учеников** — пользователи, которых создатель когда-либо
   пригласил хотя бы на один свой курс (уникальные по всем его курсам).
2. Переход на **страницу пользователя в контексте курсов**: только курсы,
   куда **этот создатель** добавил данного пользователя (не чужие курсы
   других создателей).
3. На этой странице / внутри каждого такого курса создатель может менять
   текущий урок пользователя — те же правила, что в §6.

## 11. Ошибки и пограничные случаи

| Ситуация | Поведение |
|---|---|
| Роль `user` открывает Cursos | Видит empty / pending / принятые; без create/invite |
| Роль `user` вызывает create / content mutate | `403` |
| Приглашение при 0 уроках | Запрещено |
| Логин не найден | Membership не создаётся, ошибка |
| Курс неэффективен (§7) | Нельзя invite / current; нет урокового окна в пуле |
| Demotion создателя | Курс деактивирован; словарь участников без удаления |
| Отклонение invite | Membership удалён |
| Убрать / выйти с курса | Membership удалён; словарь без изменений |
| Current = последний урок | Остаётся `accepted`; в списке ниже тех, у кого есть следующий |
| Два эффективных `accepted` курса | Окна объединяются в пуле дня |

## 12. Критерии приёмки

- **COURSE-01:** создавать курс могут только `teacher`/`admin`.
- **COURSE-02:** уроки только внутри курса; `user` видит Cursos (empty /
  invite / принятые), без create/edit.
- **COURSE-03:** приглашение невозможно без ≥1 урока и без эффективной активности.
- **COURSE-04:** invite несуществующего не создаёт membership; любая роль
  target — ок; self-invite → сразу `accepted`.
- **COURSE-05:** pending на Cursos у любой роли; accept/reject без email.
- **COURSE-06:** после accept current = первый; словарь по окну уроков.
- **COURSE-07:** reject удаляет membership.
- **COURSE-08:** участник — свой current; создатель — ещё чужие
  (на эффективном курсе).
- **COURSE-09:** отдельного статуса `completed` / кнопки Completar нет.
- **COURSE-10:** список Cursos: эффективные `accepted` не на последнем сверху;
  деактивированные ниже.
- **COURSE-11:** участники курса: `pending`, затем не на последнем, затем на последнем.
- **COURSE-12:** Alumnos → страница пользователя в контексте курсов.
- **COURSE-13:** неэффективный курс без урокового окна и без новых invite;
  участник не открывает страницу курса, создатель — да.
- **COURSE-14:** пул объединяет окна всех `accepted` + эффективно активных курсов;
  слова уже в словаре остаются в тренировках.
- **COURSE-15:** участник не редактирует чужой контент курса.
- **COURSE-15b:** создатель убирает участника / участник выходит —
  membership удалён, словарь не чистится; повторный invite возможен.
- **COURSE-16:** demotion создателя → деактивация; словарь не чистится.
