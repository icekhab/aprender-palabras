# Подсказки перевода

## Границы функции

Поиск пар перевода из общей таблицы `Word` (быстрый) и через OpenAI
(медленнее), с обогащением из личного словаря (`UserCard`) текущего
пользователя.

Поведение:

- пользователь вводит слово, фразу или незавершённый префикс в поиске на главной;
- панель подсказок видна только пока инпут в фокусе; при blur скрывается,
  при повторном focus показывается снова (если запрос ещё достаточно длинный);
- frontend после debounce 300 ms и при длине от 2 символов отправляет
  **два** запроса параллельно (если доступен AI):
  1. `GET /suggestions/db` — word-boundary prefix по `spanish`/`russian`;
  2. `GET /suggestions/ai` — OpenAI autocomplete;
- как только пришёл ответ БД — показываем его и лейбл «Buscando con IA…»;
- ответ AI мержится **после** ответа БД: строки из БД сверху без сдвига
  порядка; AI-only ниже; дубли пар (нормализованные spanish+russian)
  остаются как из БД;
- если AI ответил раньше БД — UI ждёт БД и показывает сразу merge;
- ошибка AI (429/503/сеть) → toast, лейбл убрать, список из БД сохранить;
- если `canUseAiSuggestions=false` (квота suggestions **или** generation
  исчерпана) — только запрос в БД, без лейбла AI;
- в AI-подсказках только словарные формы (леммы): без склонения и без
  разворота спряжений;
- UI действий по строке:
  - нет `wordId` — у **admin** клик открывает `/words/new?...` (полный
    мастер); у **user** — автогенерация и сразу add (без экрана правки),
    у **teacher**/**admin** — полный мастер;
    с проверкой квоты генераций;
  - есть `wordId`, нет в личном словаре — иконка «+», `POST /words/existing`
    (без платных API, без квоты генераций);
  - уже в личном словаре — иконка прогресса (как в Diccionario).

Дневная квота suggestions (`Europe/Madrid`): **450**/день для `user`,
**600**/день для `teacher`; `admin` без лимита; override
`User.dailySuggestionsLimit`. AI-ветка также требует свободную квоту
генераций (check без consume). См. [quotas.md](./quotas.md).

## Направление перевода

| Ввод | Направление |
|---|---|
| Есть символы кириллицы | русский → испанский |
| Нет символов кириллицы | испанский → русский |

Направление влияет на сортировку БД-выдачи (меньше слов на стороне
языка ввода — выше) и на промпт OpenAI.

## Поиск по базе (word-boundary prefix)

Не mid-word `LIKE`: токены запроса должны быть префиксами **последовательных
слов** в `searchSpanish` / `searchRussian` (accent-folded).

Перед сравнением и `q`, и поля проходят `normalizeSearchKey`
(lower + снятие диакритики + `ё`→`е`): и `car`, и `cárc` находят `cárcel`.

| Запрос | `consentir` | `el coche` | `sentir` | `cárcel` |
|---|---|---|---|---|
| `sentir` | нет | — | да | — |
| `coche` | — | да | — | — |
| `el coc` | — | да | — | — |
| `car` / `cárc` | — | — | — | да |

Лимит БД: до 20 строк после ранжирования.

## REST API

Все маршруты находятся под префиксом `/api`. Требуется активная сессия.

### `GET /suggestions/db?q=...`

Без квоты. Word-boundary prefix по `searchSpanish`/`searchRussian`
(после fold `q`) + progress из `UserCard`.

### `GET /suggestions/ai?q=...`

Query-параметр `q` (оба endpoint):

- обязателен;
- после `trim` мин. 1 символ; макс. по направлению: без кириллицы —
  испанский (≤100 символов, ≤10 слов); с кириллицей — русский
  (≤120 символов, без лимита слов);
- клиент может debounce и слать запрос от 2 символов; сервер принимает от 1;
- для AI: модель угадывает завершения и их переводы (до 8 пар).

Перед OpenAI: `assertGenerationAvailable` + `consumeSuggestions`.

Успешный ответ `200` (оба endpoint):

```json
{
  "suggestions": [
    {
      "spanish": "esperar",
      "russian": "ждать",
      "wordId": "word-uuid-or-null",
      "progress": null
    }
  ]
}
```

| Поле | Значение |
|---|---|
| `wordId` | `id` из `Word`, если пара уже есть в общей базе; иначе `null` (AI) |
| `progress` | прогресс `UserCard` текущего пользователя (`inDictionary=true`); иначе `null` |

Ошибки:

| Статус | Когда |
|---|---|
| `400` | невалидный `q` |
| `401` | нет сессии |
| `429` | AI: дневная квота suggestions или generation исчерпана (не-admin); OpenAI не вызывать |
| `503` | AI: нет `OPENAI_API_KEY` или сбой OpenAI |

`AuthUser.canUseAiSuggestions` отражает, можно ли слать AI-запрос
(оба дневных лимита свободны; admin всегда `true`).

## Переменные окружения

```dotenv
OPENAI_API_KEY=
OPENAI_MODEL=gpt-6-sol
```

Приложение должно запускаться без ключа OpenAI. В этом случае AI-endpoint
отвечает `503`, а поиск по БД и остальной функционал остаются доступны.
