# Авторизация

## Границы функции

На текущем этапе доступны вход, восстановление серверной сессии и выход.
Самостоятельная регистрация в UI **не** реализуется. Пользователей создают
миграциями (или иным административным способом) с хешем пароля Argon2id.

Тестовый пользователь из начальной миграции:

- логин: `icekhab@gmail.com`;
- пароль для локального входа: `123345`;
- целевая роль: `admin` (после миграции ролей).

В базе данных хранится только Argon2id-хеш пароля. Логин сравнивается без учёта
регистра.

## Роли

| Роль | Назначение |
|---|---|
| `user` | Словарь и тренажёры; **нет** доступа к API/UI курсов |
| `teacher` | Курсы: создание, прохождение, приглашения (см. [courses.md](./courses.md)) |
| `admin` | Права teacher по курсам + каталог/правка любых `Word` |

Поле `User.role` (default `user`). Ответ `login` / `GET /auth/me` включает
`role`. Все маршруты `/api/courses*` требуют `teacher` или `admin` (`403`
иначе).

Nullable override квот (null = дефолт, см. [quotas.md](./quotas.md)):

- `dailySearchGenerationLimit` (дефолт 20);
- `dailyTotalGenerationLimit` (дефолт 100, поиск + курсы);
- `dailySuggestionsLimit` (дефолт 300).

Плюс счётчики текущего дня Madrid и `quotaDate`.

Правила редактирования слов — [words.md](./words.md),
[product/01-words.md](../product/01-words.md). Курсы — [courses.md](./courses.md).

## Создание пользователя миграцией

1. Сгенерировать Argon2id-хеш пароля (параметры как у приложения).
2. Вставить строку в `User` с уникальным `normalizedLogin` (NFKC + lower).
3. При необходимости указать `role = 'admin'` или `role = 'teacher'`.

Пример хеша для локального пароля `123345` уже есть в миграции auth seed.

## Сессии

После успешного входа backend создаёт криптографически случайный непрозрачный
токен. В PostgreSQL хранится только его SHA-256-хеш. Сессия действует 30 дней
с момента входа и не продлевается автоматически.

Токен передаётся cookie `aprender_palabras_session` со свойствами:

- `HttpOnly`;
- `SameSite=Lax`;
- `Path=/`;
- `Secure` в production; локально флаг отключён для работы через HTTP;
- `Expires`, совпадающий со сроком сессии.

Изменяющие запросы принимаются только с заголовком `Origin`, точно совпадающим
с `APP_ORIGIN`. Выход удаляет текущую сессию из БД и очищает cookie.

## REST API

Все маршруты находятся под префиксом `/api`.

### `POST /auth/login`

Публичный маршрут. Принимает JSON:

```json
{
  "login": "icekhab@gmail.com",
  "password": "123345"
}
```

При успехе возвращает `200` и безопасные данные пользователя:

```json
{
  "id": "uuid",
  "login": "icekhab@gmail.com",
  "role": "admin"
}
```

Неизвестный логин и неверный пароль всегда дают одинаковый `401`, чтобы не
раскрывать наличие пользователя. Невалидный JSON даёт `400`, превышение лимита
попыток — `429`. Текст API-ошибок возвращается на английском языке; frontend
показывает пользователю соответствующее сообщение на испанском.

### `GET /auth/me`

Возвращает безопасные данные текущего пользователя (включая `role`).
Отсутствующая, неизвестная или истёкшая сессия даёт `401`.

### `POST /auth/logout`

Удаляет текущую сессию, очищает cookie и возвращает `204`.

## Защита остальных API

Авторизация включена глобально. Публичными являются только маршрут входа и
технический `GET /api/health`, используемый healthcheck контейнера. Все
продуктовые маршруты по умолчанию требуют действующую сессию. Публичные
маршруты должны явно отмечаться соответствующим декоратором.

Маршруты `/api/admin/*` дополнительно требуют `role === admin` (иначе `403`).
